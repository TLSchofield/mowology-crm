# Guardian — deterministic verification (no model)
Runs every night inside Ada's cycle (needs no Claude sign-in) and on every merge (the rules part).
- **Rules ratchet** `rules.py` — CLAUDE.md rules (no inline `<style>` in CRM pages, no hard-coded hex, no raw `mail()`, no visible `type=date`, MySQL 5.7-only SQL, no committed secrets). Existing violations are in `baseline.json`; a file may only get better. Enforced by `tests/Unit/Docs/GuardianRulesRatchetTest.php`, so the merge gate refuses new violations. After cleaning up: `python3 scripts/guardian/rules.py --tighten`.
- **Page audit** `page-audit.mjs` — real Chrome (headless), public pages from `scripts/sentinel/targets.json`, at 375/768/1440 px: load status, sideways scroll, page weight, LCP/CLS, axe-core accessibility, tap targets under 44 px, text under 12 px, headings, alt text, labels, console errors, failing requests, broken internal links, robots.txt/sitemap. Screenshots saved. Tools (pinned `playwright-core`, `axe-core`) live in `~/.mowology-guardian/node_modules`, outside the repo; `scripts/dept/install.sh` installs them.
- **Findings** `guardian.py` turns measurements into P0-P3 findings (key, severity, evidence). New ones enter Ada's queue (P0/P1 as critical, P2/P3 as ordinary, max 3 ordinary waiting for you); fixed ones close themselves; trends are kept in `~/.mowology-guardian/history.jsonl`; the latest numbers go to Sentinel as evidence.
Not covered yet (needs your go-ahead): signed-in CRM pages, the iOS/Android apps, security testing, API contract tests. Guardian never writes to the repo, never touches customer data, and never marks anything verified on its own say-so for release.
