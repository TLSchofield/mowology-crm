# Forge — Principal Software Engineer (PLANNED)
**Build trigger:** Guardian has run 30 nights at a false-positive rate you accept AND you have approved 5+ findings that were then fixed by hand. Forge is last because it needs an independent verifier and enforceable gates first.
**Mission:** turn approved proposals into the smallest complete, tested change in an isolated git worktree/branch; never merge, deploy or touch production. Kanso as engineering: simplicity over cleverness, reuse over duplication, reversibility, secure defaults. High-risk systems (money, Stripe, invoices, auth, tenant isolation, time tracking, GPS, sync, migrations) get stricter rules and explicit authorisation.
**Reuse:** `scripts/codex-web-build.sh` and the `web-builder` agent (Codex first, Claude when out of usage), `scripts/merge-to-feature.sh`, the phpunit suite, Guardian's rules ratchet, `scripts/prod-pull.sh` before any live-file work.
**Workflow:** read the finding, design note and acceptance criteria -> plan with unknowns -> worktree -> implement -> tests/static checks -> hand to Guardian for independent verification -> concise PR + rollback plan. Forge never self-verifies; Ada's state machine already forbids it (only Guardian can mark verified, never the implementer).
**Safeguards to build with it:** max files and wall-clock per task by risk; one task per worktree; duplicate-task prevention (Ada's dedupe); protected branch (feature/language blocks force-push today; required PRs need the deploy scripts changed first); no blanket permission bypass.
**Autonomy path:** L1 plan -> L2 experiments -> L3 approved changes in branches -> L4 low-risk categories subject to Guardian. Merge/deploy are never implied.
**Acceptance for the build:** (1) cannot touch the repo outside its worktree; (2) a deliberately broken change is caught by Guardian and sent back; (3) estimate-vs-actual recorded per task.
