Sidebar transitions: five solutions

Same sidebar, same six pages, five ways of moving between them. Click through each one, fast and slow. The "Sidebar built N s ago" counter at the bottom of the sidebar resets to 0 if the sidebar is rebuilt; if it keeps counting, the sidebar was never reloaded. Each has a normal and a slow server (400 ms per page, like a busy PHP page) link. Run python3 serve.py first.

A. Full page loads, with view transitions

reloadsThe browser still loads each page, but the old and new sidebar are drawn as one picture (it holds still), the highlight glides between items, the content fades, and the first paint waits until the sidebar exists.

Changes needed in the CRM: a few lines of CSS and one tag per page. Works with every existing page script.

TryTry on slow server

B. Soft navigation (pjax)

no reloadClicks are caught, the highlight moves at once, the next page is fetched and only the content area is swapped, inside one view transition. The sidebar is never touched.

Changes needed: a small script, plus every page's own scripts must be re-run after a swap (the risk in the CRM).

TryTry on slow server

C. Sidebar in a shell, pages in a frame

no reloadThe sidebar lives in one outer page and each page loads inside a frame. The pages keep all their own scripts exactly as they are.

Changes needed: a shell page; pages drop their own sidebar. Cost: frames need care for dialogs, scrollbars, deep links and printing.

TryTry on slow server

D. Full page loads, prepared in advance

reloadsLike A, but the browser builds the next pages in the background before you click (prerender), so the page you click is already finished and the switch is instant even on a slow server.

Changes needed: A plus one rules block. Chrome and Edge only; other browsers fall back to A. Costs extra server work (every menu page is built ahead).

TryTry on slow server

E. Navigation API with ahead-of-time fetching

no reloadLike B, but every navigation (links, back, forward) goes through the browser's own Navigation API, the next page is fetched as soon as you hover or press, and the highlight is optimistic. Fastest feel without a reload.

Same risks as B, with cleaner back/forward and scroll handling. Chrome and Edge; others fall back to normal loads.
