# Local test site

A private copy of the Mowology CRM that runs on this Mac at **http://localhost:8000**, with the
production database structure and fake data.

**Rule: test here before production.** Any change to a CRM page, API, service or migration is
opened on the local site (and `scripts/local-site.sh smoke` is run) before it is uploaded.
A page that fatals locally shows the error on screen. On production the same fatal is a
silently truncated page that still returns HTTP 200.

## Commands

```bash
scripts/local-site.sh start    # start MySQL + PHP. The first run also builds the database
scripts/local-site.sh status   # what is running, table count, captured mail
scripts/local-site.sh smoke    # smoke test: every role, key pages, role gates
scripts/local-site.sh reset    # drop the database, reload the schema, run local-only migrations, re-seed
scripts/local-site.sh mail     # follow the captured-mail log
scripts/local-site.sh stop     # stop both servers
```

Run `reset` after a new production backup (`scripts/prod-backup.sh`) to pick up schema changes,
and whenever you want clean data. Every reset makes new passwords.

## Logging in

Open http://localhost:8000/loginAuth/login.php. The logins are in
**`scripts/local/.credentials.local`**. That file is gitignored and is rewritten on every reset.
Its layout is shown in `scripts/local/.credentials.local.example`.

| Role    | Email              | Users table           | RBAC role |
|---------|--------------------|-----------------------|-----------|
| admin   | admin@local.test   | `admin`               | admin     |
| manager | manager@local.test | `manager`             | manager   |
| crew    | crew@local.test    | `user`, `is_driver=1` | staff     |

The same file has a customer-portal invoice link (`/customer/invoice.php?token=…`).

## What is real and what is faked

| Thing | Local behaviour |
|---|---|
| Database structure | Real. `scripts/local/extract-schema.php` streams the newest `~/Backups/mowology/mowology-db-*.sql.gz` and keeps **only** `CREATE TABLE`/`CREATE VIEW`. It throws away every `INSERT` and strips `AUTO_INCREMENT` counters. The schema is cached at `~/.mowology-local/schema.sql` and is never put in the repo. 408 tables and 1 view from production, plus 13 from migration 1331 (`LOCAL_MIGRATIONS` in `local-site.sh`). |
| Data | Fake. `scripts/local/seed.php` adds 11 invented clients, each with a company, contact and property. It also adds 5 quotes, 1 contract, 6 job plans with visits this week, 6 invoices (draft, sent, paid, overdue, partial), 4 expenses and 3 vendors. Emails end in `.test` and phone numbers use 555. Reference rows (roles, permissions, chart of accounts, tax rates, service types and so on) are replayed from the repo's own `database/migrations/*.sql`. **No production rows are ever loaded.** |
| Config | `public/app_config/secrets.php` is generated by `scripts/local/make-secrets.php`. It is gitignored and its header says `LOCAL TEST ONLY`. Internal secrets (JWT, unsubscribe, CMS preview and others) are random. The script will not overwrite a secrets.php that lacks that header. |
| Email and SMS | Never sent. `SMTP_HOST` is blank, so the CRM falls back to `mail()`. `sendmail_path` points at `scripts/local/sendmail-log.sh`, which only appends to `~/.mowology-local/mail.log`. `SMTP_USER`/`SMTP_PASS` and the IMAP passwords are undefined, so no mailbox poller can connect. |
| Stripe, Anthropic, Google, Meta, OCR, reCAPTCHA, Trackimo | Keys are blank or obviously fake (`pk_test_LOCAL_FAKE…`, `LOCAL-FAKE-MAPS-KEY`). Maps and other Google widgets do not load. |
| APNs and FCM push | Keys are undefined. Nothing can be pushed. |
| Outbound HTTP from PHP | The PHP server runs with `http(s)_proxy=127.0.0.1:9`, a dead proxy. Every cURL call to the internet fails at once. `localhost` is exempt. |
| Cron jobs | Not scheduled. Run one by hand only if you mean to. |
| Hosting | PHP 8.3 built-in server with `scripts/local/router.php`. The router copies production's `.htaccess`: the `/api/<module>/<action>` rewrite (QSA order included), the CMS catch-all to `cms-render.php`, the named clean URLs, the canonical 301s and DirectoryIndex. It also denies `app/`, `vendor/`, `storage/`, `sessions/`, `app_config/`, dotfiles, `*.md`/`*.sql`/`*.log` and the config files. |
| PHP settings | `scripts/local/php.ini`: `display_errors` is on and OPcache revalidates on every request, so edits show at once. Sessions are stored in `~/.mowology-local/sessions`. `allow_url_fopen` is off, as on production. |

The app logs `Session save path not writable or missing: /home/mowology/tmp` on every request.
This is harmless: the production path does not exist here, and the session falls back to the
local path.

## Where things live

* Scripts: `scripts/local-site.sh`, `scripts/local/` (router, php.ini, seed, smoke, extract-schema, make-secrets, sendmail-log).
* State, outside the repo: `~/.mowology-local/` holds the MySQL data dir and socket, the schema
  cache, the DB password, sessions, `php-server.log`, `php-error.log` and `mail.log`. Override it
  with `MOWOLOGY_LOCAL_STATE`.
* Binaries: Homebrew `mysql@8.0` and `php@8.3` when installed. Otherwise MAMP's
  `mysql80` and `php8.3.30`, run on their own data dir (MAMP's own MySQL is untouched).
* Ports: the site is on 8000 (`LOCAL_SITE_PORT`). MySQL listens on 3307 (`LOCAL_DB_PORT`) and on a unix
  socket, bound to 127.0.0.1 only. MySQL root has no password and is reachable only through the socket.

## Smoke test

`scripts/local-site.sh smoke` logs in as admin, manager and crew. For each role it opens the dashboard, schedule,
a job, the invoices list and one invoice, clients, quotes, a contract, reports, settings, users
and supplier price lists. It also opens the customer-portal invoice through its token. It checks:

* the status each role should get (200, or 403 where the role is gated out);
* that the page renders to `</html>` with no `Fatal error`, `Warning:` or `Uncaught` text;
* the crew gates: clients bulk delete, contract edit, reports and users must all be refused;
* that the router denies production's protected paths.

When `import playwright` works (`pip3 install playwright`), a second pass renders each page in the
installed Google Chrome and reports JavaScript errors. Requests to any host other than localhost
are blocked. `--http` skips that pass.

## Android emulator — the crew app as a founding business sees it

`scripts/local-android.sh up` runs the crew app (the `tenanttest` flavor of `~/Projects/mowology-android-codex`)
on an Android emulator against a **second business** on this local site, at `https://claudia.ittai.ca`, with
every `android.native_*` switch on. Nothing touches production; the build refuses `mowology.ca` by design.

How the pieces fit:

| Piece | What it does |
|---|---|
| `scripts/local/provision-tenant.php` | `TenantProvisioner` with MySQL-on-the-socket standing in for cPanel: database `mowology_<key>`, `public/app_config/tenants.php` entry, uploads folder, owner login (password appended to `.credentials.local`). |
| `scripts/local/seed.php` with `MW_TENANT=<key>` | The same fake data into the tenant's database; its own fake mail domain (`@<key>.test`), `LOCAL_SEED_TRADE` / `LOCAL_SEED_CITY` for BusinessIdentity. Logins are appended, not overwritten. `scripts/local-site.sh php …` runs any script with the site's php.ini and socket. |
| `scripts/local/tls-proxy.py` | HTTPS on 127.0.0.1:8443 with a local CA (`~/.mowology-local/tls`), forwarding to the PHP server unchanged. The app only speaks https to a bare hostname, and `Tenant.php` picks the business from the Host header. |
| `scripts/local/app-version.local.json` (gitignored) | Copied from `app-version.tenanttest.json`; `router.php` serves it as the crew-app feed, so the repo's `app-version.json` is never edited for a test. |
| Emulator (AVD `claudia`, API 34 google_apis x86_64) | `-writable-system` so `/system/etc/hosts` maps `<key>.ittai.ca` → 127.0.0.1; `adb reverse tcp:443 → 8443`; the local CA goes in the user store, which the **tenanttest debug build** trusts through `debug-overrides` (`src/tenanttest/res/xml/network_security_config.xml`, ignored by release builds). Renderer `angle_indirect`: swiftshader never finished booting on the iMac and `-gpu host` hung QEMU. |

Commands: `up` (all of it, re-runnable), `build`, `install`, `logins`, `status`, `down`. Settings by env:
`TENANT_KEY`, `TENANT_NAME`, `TENANT_TRADE`, `TENANT_CITY`, `ANDROID_DIR`, `AVD`, `GRADLE_OFFLINE=1`.

Driving the emulator by hand is slow (about two frames a second on the iMac): `adb shell input text` drops
characters unless typed in short chunks, Back with no keyboard up quits the app, and taps must be aimed after a
fresh screenshot because the layout shifts with the keyboard and with error banners.
